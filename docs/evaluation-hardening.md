# 0.9.1 收尾修复

## 直接回答错误提示

任务层仍采用原有首条失败原因作为 error_code 的约定。直接回答的固定“未经核验”说明继续保留，但模型未配置、供应商失败、JSON 无效、伪造引用等失败原因放在它前面，供任务页面与评测工件定位问题。没有将直接回答升级为已核验结论。

## 损坏工件处理

校验和只能证明内容一致，不能证明 JSON 嵌套字段符合协议。报告读取增加结构校验，先确认 task、snapshot、report、usage 是对象，claims、evidence 和评分组是正确列表，标识和证据引用是字符串，再进行原有身份、快照、引用与人工裁决校验。

- 单题结果、该题依赖的快照准备记录结构损坏：该计划槽位标为 invalid，其他题继续汇总；槽位不从分母消失，正式完成率与完整费用总量保持未知，不把坏数据当作0。
- 共享 context 或共享建库工件损坏：停止本次报告生成，返回可识别的输入错误；这些元数据无法信任时不发布汇总。
- 人工评分包、单项裁决或引用列表结构错误：拒绝本次评分输入，保留原文件；不能静默忽略评分或跳过来源检查。

正确格式的原始结果仍可读取；没有改写旧运行工件、评分结果、预算或调查内容。校验和不是数字签名，操作者能重写全部工件时，不提供真实性保证。极深 JSON、文件系统异常及其他未覆盖损坏情形不属于本次完整运行验收。

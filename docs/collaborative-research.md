# 协作调查增量（0.3.0 / V2.0）

默认 single 保留原调查流程；新建分析可选择 collaborative。追问继承当前模式和固定快照。API `POST /tasks` 的 `mode` 缺省 single，`GET /tasks/{id}/graph` 返回公开计划、子任务、补查轮次与模型评审摘要。旧任务 JSON、旧幂等记录和旧 Markdown 引用继续可用。

实际 LangGraph StateGraph 由 Planner、code/docs 调查、Reviewer 与确定性 Reporter 组成。首次最多四个无环子任务，实际模型请求峰值为二；最多两轮、每轮两个针对性补查，没有新证据即停止。Planner/Reviewer JSON 只修正一次，计入总预算。Reporter 仅归并已有、已观察并复核过的引用，不调用模型增加事实。

所有角色共享原有总上限：30 次模型请求、30 次工具调用、60,000 输入加输出 token、900 秒。每个协作子任务另有累计八次工具上限。预留原子化；模型重试和 JSON 修正都计费。失败或缺 usage 的请求保留保守估算，不能当成零用量。单角色请求由统一 ModelGateway 发出。

供应商实际用量任一分量超过该次预留时锁存停止，仍如实结算在途请求；其他请求释放额度不会重新开放调用。在 `model_started` 持久化后再次检查取消/截止时间，尚未发送的请求撤回预留，不计为供应商用量。

文档限同一快照已纳入的 Markdown/RST/TXT、README/LICENSE/COPYING/CHANGELOG；不打开外部网页，也不回读原仓库补证据。代码和文档的读取范围由服务端强制隔离。模型判断单独标为“模型评审”，只校验引用位置不等于验证语义。冲突、缺证据、失败分支、预算或轮次耗尽会明确 partial。

协作模式缺代码或仓库文档时始终公开缺口并 partial，即使 Planner 省略对应角色。此规则较保守：纯代码问题也可能因无文档而部分完成，可选择 single 完成纯代码调查。Reviewer 单轮最多接收十二份原文；超出范围的结论保留未评审并 partial，不允许仅凭其他角色观察过引用便标记模型支持。

图详情和 SSE 事件保存于现有 SQLite。终态、报告、图状态与总用量同事务提交。取消等待在途调用结算后停止；running 在重启时标记 interrupted，没有 checkpoint、resume 或持久图恢复。单 worker 管理一项调查，不能使用多进程共享数据库。

## 独立审查与修复

全分支独立审查覆盖 f660040..937c2b3，发现八项重要问题，无 Critical。以下均先复现失败，再一次修复并通过针对性回归：

| 问题 | 修复与回归 |
|---|---|
| 无工具请求仍发送工具字段 | 空工具请求省略 tools/tool_choice；本地 HTTP transport 同时检查有/无工具请求 |
| 超预留后可能重新开放调用 | 原子锁存异常；在途请求释放后仍不能新预留 |
| Send 兄弟分支结果丢失 | 子任务边界隔离意外异常，保留另一分支及公开失败结果 |
| 第十三份引用未送 Reviewer 仍获支持 | 只允许真正送审的引用和结论，其他保留未评审 |
| Planner 省略 docs 隐藏文档缺失 | 根据快照实际范围强制公开资料缺口 |
| 最终复核失效或抛异常导致假成功/终态分裂 | 单条无效即 partial；意外 worker 错误也原子保存图、用量及失败报告 |
| 失败搜索留下未展示的引用 | 错误结果清空不完整证据；Agent 只接受成功工具返回的引用 |
| 取消发生在开始事件持久化期间仍发请求 | 供应商入口前重查，撤回尚未发送预留；在途调用仍结算 |

另将“新建分析沿用上次协作选项”按潜在调用差异升为重要问题并修复，保留失联重试和追问的模式继承。上述针对性回归 59 项通过。

暂缓的一项轻微问题：分工卡片在子任务执行中、或图已停止但仍有未派发计划项时，可能显示“等待中”；调查时间线和任务终态仍反映实际事件。
